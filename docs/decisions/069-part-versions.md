# 069 — У каждой части своя версия

2026-10-29. Замечание автора: «версия всех плагинов отображается как 1.0.0 — не норм, мы не сможем выпускать независимо версии плагинов с доработками, мб уроков».

## Что было не так

У приложения версия бралась из git-тега (ADR 012). У `juce_add_plugin` для Learner EQ / Comp / Verb `VERSION` не было задано вовсе, поэтому VST3/AU сообщали хосту заводскую 1.0.0. Кнопка «Проверить обновления» в плагине сравнивала с тегом *версию приложения*: любой выпуск приложения выглядел как обновление каждого плагина, даже если плагин не менялся.

## Решение

`versions.json` в корне — единственное место, где записаны версии частей:

```json
{ "app": "2.2.0", "learner-eq": "2.2.0", "learner-comp": "2.2.0", "learner-verb": "2.2.0", "lessons": "1.0.0" }
```

- **Выпуск по-прежнему один.** Один тег, один установщик со всем внутри: так проще ставить и нельзя получить Studio от одной версии, а плагин от другой. Номер части поднимается, только когда меняется сама часть.
- **CMake** читает файл и отдаёт номер плагина в `juce_add_plugin(... VERSION ...)`. Это то, что видит DAW. Номера частей попадают в `VersionInfo.h`, оттуда в `CurrentVersion::of (Part::learnerEQ)`. Приложению `VERSION` берётся из тега, раньше там тоже стояла 1.0.0.
- **Проверка обновлений.** Рабочий процесс выпуска дописывает в конец текста релиза строку `<!-- versions: {...} -->` из `versions.json`. API GitHub отдаёт текст релиза в том же ответе, что и тег, поэтому лишнего запроса нет и правило «один запрос» (ADR 042) не нарушается. Плагин сравнивает свой номер с номером в этой строке. У старых релизов строки нет, тогда сравниваются тег и версия приложения, как раньше.
- **`tools/release.py`** проверяет, что `app` совпадает с тегом. Если с прошлого тега менялись файлы части (`LearnerEQ/`, общие `shared/dsp`, `shared/learning`, `shared/analysis`, `lessons/`), а её номер нет, скрипт предупреждает. Не запрещает: правка в `shared/` не обязательно меняет плагин, решать человеку.
- **«О программе»** показывает версию приложения и строкой ниже номера плагинов и уроков.

## Как поднимать

SemVer по смыслу для того, кто пользуется:
- исправление — патч: 2.2.0 → 2.2.1;
- новая возможность или урок — минор: 2.2.0 → 2.3.0;
- то, что ломает сохранённые проекты, — мажор. ID плагина и параметров не меняем (CLAUDE.md), так что мажор у плагинов почти невозможен.

Номер поднимается в том же PR, что меняет часть (шаблон PR напоминает).

## Почему не отдельные установщики на каждый плагин

Обсуждали третий вариант: свои теги и установщики для каждого плагина. Это втрое больше работы в CI и подписи, а пользователь, у которого стоит всё, будет обновлять три вещи вместо одной. Если понадобится выпустить один плагин срочно, это патч-выпуск всего установщика, где поднят только его номер.
